# Aether を参考動画（0.53.09）へ近づける手順

対象動画: `画面収録 2026-08-07 0.53.09.mov`  
スタイル: `?style=aether`（DEV）

---

## 方針（2026-08-07 改訂）

**問題の本質**は係数不足ではなく、生成原理の取り違えだった。

| | 以前（失敗しやすい） | いまの方針 |
|--|--|--|
| 形 | 48³ に球スタンプで堆積 | **解析 SDF（柔らかいトーラス）＋ domain warp** |
| 手順 | 音と見た目を同時に作る | **無音でも似ているベースを先に** → 音は変調 |
| 色 | 位置極／粗い密度ランプ | SDF密度 → Beer-Lambert の色ランプ |

Midjourney 等は **目標固定用のムードボード** には有効だが、場そのものにはならない。

---

## 1. 参考動画がやっていること

- 背景: フラットな淡ミント
- 形: メタボール／歪んだトーラス状の一体塊、中央に暗いボイド
- 縁: 背景に溶ける
- 色: 縁ミント → 中間橙 → 奥は黒紺（密度／光学深度）
- 動き: ゆっくりした連続変形（細枝・粒子チカチカが主役ではない）

技術推定: SDF＋ノイズ歪み＋体積レイマーチ（スタンプ彫刻ではない）。

---

## 2. 実装の骨格（現行）

ファイル: `src/aether-sculpture.ts`

1. **ベース場（無音）**  
   - `sdTorus` を `smin` で少し非対称化  
   - `fbm` / `noise` による domain warp  
   - SDF → soft density → Beer-Lambert（高密度は黒く沈む）
2. **音はパラメータ変調のみ**  
   - kick / low → `major` / `minor` / 吸収のパルス＋`accumMass`  
   - mid / snare / melody → `warp` / stretch / twist＋`accumWarp`  
   - hat / high → `uWarpFine`＋`accumFine`  
   - ボクセルへ球を積まない
3. **背景**  
   - `AETHER.env` は淡ミント平面（vita 深海は使わない）
4. **パフォーマンス**  
   - レイステップ 48・sin系 cheapNoise・空空間スキップ  
   - aether ではブルーム無効（シーン再描画が重いため）

確認: 曲を止めて（または再生前に）すでに「光のリング状の塊」に見えること。

## 3. さらに寄せるときの優先順

### A. 静止見た目（最優先）

1. `baseMajor` / `baseMinor` / `baseWarp` / `baseSoft`  
2. `densityRamp()` の停止点（ミント／橙／黒の位置）  
3. `uAbsorption` / `uEmission`（穴の沈みと中間の光）  
4. warp のスケール（大きすぎるとぐちゃぐちゃ、小さすぎるとドーナツそのもの）

### B. 動き（音）

1. パルスは大きく・短く（細かいチカチカにしない）  
2. 蓄積は遅く（長い曲で溶けてブロブにしない）  
3. 形のトポロジー（穴）を壊す変調は避ける

### C. 参照の増やし方

1. `0.53.09` から静止フレームを切り出す  
2. 必要なら Midjourney 等で同系統を追加（同じ背景色・同じ構図）  
3. 注釈: シルエット／中央の黒／橙の帯／縁の溶け幅  
4. **無音スクショ** をそれと並べて合否を見る

---

## 4. やってはいけないこと

- 球スタンプ堆積や MarchingCubes に戻す  
- vita 深海背景を「雰囲気継承」で戻す（見た目目標が崩れる）  
- ベースが似ていない段階で音マッピングを細かく詰める  
- Midjourney 画像をそのまま立体の本体にしようとする

---

## 5. 原則との関係

- aether では「光の体積としての完成形」を採用（塑体メッシュではない）  
- リアルタイム = LIVE パルス、蓄積 = accum*、完成 = パルス停止＋蓄積の固定／強調  
- 低→質量／中→伸長歪み／高→細うねり、はパラメータ層で維持
