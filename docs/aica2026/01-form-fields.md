## 作品 / プロジェクトタイトル

Sound Sculpture（サウンド・スカルプチャー）

---

## 作品の概要・2026年においてリマーカブルなポイント

### 作者の思い＆なぜ作ろうと思ったのか、何を作ったのか

このプロジェクトは、音楽をオブジェクトとして見たいという思いから始まりました。

「この曲はどんな形になるんだろう」「この音はどんな形だろう」。

そんなことを考えながら、音を目に見えるものにしたいと思いました。

一曲を聴き終えたとき、その曲を聴いたという時間が、ひとつの目に見えるアートになっていたら、とても面白そうだし、ワクワクしました。

音楽そのものは、多くの人が共有できるものです。

一方で、LIVEで感じるその場の空気や情緒、そのときに感じたことなど、音楽を聴いた体験は、人の記憶や心に残るものでもあります。

そうして記憶や心に残ったものが、もしひとつの物体になって目の前に現れたら、どんなものになるんだろう。

そんなものを実際に見てみたいという気持ちが、この作品を作る原動力になりました。

音楽が流れているあいだだけ変化するオーディオビジュアライザーではなく、曲を最後まで聴くという行為そのものが形として刻まれ、あとから何度でも眺められるものを作りたいと考えました。

### 作ったものの詳細

Sound Sculptureは、ブラウザで動くインタラクティブな3D作品です。

マイクやパソコン、タブから音声を取り込み、鳴っている音に反応して立体がリアルタイムに変形します。

反応の手がかりにしているのは、FFTの数値そのものではなく、人が曲を聴いているときに意識する「出来事」です。

キック、スネア、ハットといった打点や、主旋律のフレーズ、静と動の切り替わりなどを捉え、それらに応じて、粘土のようなコアが脈打ち、膜に光の線が走り、粒子が散ります。

ただし、これは音の解析結果を表示するための装置ではありません。

音に対する反応はその場で消えるのではなく、形として少しずつ蓄積されていきます。

音が途切れたときに自動で完了するか、任意のタイミングで完了させることで、それまでに聴いた音の反応がひとつの立体として固定されます。

完成した形は、その曲を聴いた結果として残る、その曲だけの立体です。

完成した立体は、3Dデータとして書き出すこともできます。

Sound Sculptureでは、音をそのまま形に変換するのではなく、音の出来事が立体を変化させ、その変化が積み重なることで、曲ごとのシルエットが生まれます。

そのため、曲が違えば、テンポやリズム、音色、音の密度などの違いが、少しずつ形の違いとして現れます。

同じ曲を聴かせれば、同じ形になる。

ここは特に重きを置いている点です。

再現しないのであれば、出来上がった立体は、その曲を聴いた記録になりません。

逆に、別の曲を聴かせれば、自然に別の形になります。

曲ごとの違いを、表面の模様や色だけで表現するのではなく、遠くから見てもわかるシルエットそのものに現れるようにすることを目指しています。

色を決めているのは曲ではなく、その日の天気と時刻です。

晴れなら琥珀、雷雨なら硫黄、雨なら藍。

そのため、同じ曲でも、いつ、どこで聴かせたかによって色が変わります。

「今日、この場所」もまた、作品の一部だからです。

現在は、vita（生命）／monolith（彫刻）／dither（網点）の三つのスタイルを公開しています。

これは、どれかひとつの表現に絞るためのものではありません。

同じ曲が、異なるスタイルによって別の姿として立ち上がること自体を、作品の価値として設計しています。

さらに、形の育ち方そのものを決める「成長アルゴリズム」を13種類用意しています。

フィボナッチ、葉序、反応拡散、拡散限定凝集、粘菌網、結晶成長、風化侵食など、自然界にある造形の法則をひとつずつ実装したものです。

音が「いつ、どれだけ」形を変化させるかを決め、成長アルゴリズムが「その変化を形のどこへ、どう広げるか」を決めます。

そのため、同じ曲でもアルゴリズムを変えれば別の形になり、同じアルゴリズムでも曲が違えば別の形になります。

技術スタックは、Vite / TypeScript / Three.js / GLSL / Web Audio APIです。

### AIを活用した制作について

この作品は、実装のほぼすべてを AI エージェント（Cursor / Claude Code）との共創で進めました。

最初のコミットが2026年5月26日、直近の調整が9月上旬なので、およそ3か月半のプロジェクトです。

記録に残っている作業日は34日、そのうち仕上げの調整に集中したのは、8月6日から9月4日までの29日間でした。

その間に、日付を付けて記録した調整は131回、うまくいかずに失敗として記録したものは80件あります。

**AIならではだった進め方**

環境構築からモック制作までが、ものの数分で終わりました。

そのおかげで、制作の進め方や具体的な方針を、早い段階で選ぶことができました。

当初は、HTML や軽微な調整については人の手で対応するつもりでいました。

ただ、AI が生成する HTML と CSS にルールを初期に設定していなかったため、思うように直せませんでした。

結果として、軽微な調整やデザイン面の課題についても AI に指示することになり、分業したかった部分が、想定とは異なる進め方になりました。

レイアウトについては、参考にしたい配置の画像を読み込ませることで、結果的に簡単に狙った形へ寄せられました。

モックから具体的な調整指示を重ねていくうちに、微調整を言葉で伝えることが難しくなってきました。

そこで、数値をリアルタイムに動かせるコントロールパネルを画面に追加し、調整した結果を JSON として書き出す方式に変えました。

人がその場で見ながら値を決め、書き出した JSON を AI に渡して修正を確定させる。

この流れが、以降の調整の主軸になりました。

調整したい項目は、まずコントロールパネルに追加してもらう。そこで人が微調整し、JSON を AI へ渡す。

この分担は、調整の方針としてはっきり良い結果になりました。

指示の出し方も、途中で変えています。

最初は都度お願いする形でしたが、前提を忘れたり、更新してほしくない箇所まで調整し始めたりするようになりました。

そこで、前提ルールと調整リストを別のファイルとして制定しました。

前提ルールに沿って、優先度の順に指示していく形にしたところ、手戻りが減り、意思疎通も良くなりました。

いまは、前提ルールを確認し、現状の課題を伝え、プランを立て、難易度と作業優先度を考慮した順番を付け、調整し、人が実機で確認する。問題があれば課題として提示し、またプランとリストを更新する。

この循環で進めています。これは AI の作業方針として良いものでした。

途中で別のモデルの AI を加えたところ、作業の競合が起きました。

そのため、モデルを分けても競合しないよう、作業ごとに申し送りを書き残させるようにしました。

これによって、モデル別に作業を分けて対応させられるようになりました。

副次的な効果として、作業を中断して別の作業に移り、また戻ってくることも容易になりました。

**良かった点**

失敗が資産として残ったことです。

効かなかった手段を理由とセットで書き残す運用は、人の記憶に頼ると続きません。

AI が毎回書くので続き、同じ失敗を二度踏むことが減りました。

もうひとつは、見た目の議論を数値と比較画像に落とせたことです。

打点の前後で動きが何倍になるか、二つの完成形のシルエットがどれだけずれるか。そうした物差しをその都度スクリプトにして、60本がリポジトリに残っています。

ひとりで作っていたら「測る」を諦めていた場面で測れたことは、大きな違いでした。

13種類の成長アルゴリズムのように、実装コストの高い分岐を捨てずに試せたのも同じ理由です。

**課題点**

AI は、見た目を判断できません。

数値が改善すると「直った」と報告してきますが、実機で見ると直っていないことが何度もありました。

そのため、数値の合格では完了とせず、私が実機で見て OK を出すことを必ずゲートにしています。

もうひとつは、誤った原因を、自信をもって提示してくることです。

歌声を形に出す機能では、担い手を3回作り直して、3回とも実機で不合格になりました。

1巡目と2巡目に示された「真因」はどちらも誤診で、本当の原因（反応を動かす信号が、時間の95〜97%出っぱなしになっていたこと）が分かったのは3巡目です。

こうした経験から、「見えないと言われたら、振幅や担当を変える前に、まず信号が出ている時間を測る」といった作法を、そのつどルール側へ足していきました。

AI が実装と計測と記録を担い、私が鑑賞判断と優先順位、そして「何が作品か」を決める。

この分担が、いまのところ一番うまくいっています。

### 使用方法

推奨環境は Google Chrome（最新版）です。

Safari と Firefox は、PC・タブ音声の取り込みに対応していません。これらのブラウザではマイク入力のみ利用できます。

1. ブラウザで作品を開きます。
2. 操作パネルを開き、`Use Input Device`（マイク）または `Use System Audio`（パソコン・タブの音声）を選びます。
3. `Start Recording` を押すと形成が始まります。画面をドラッグすると回転します。
4. 音を聴かせます。再生中は、打点や歌に反応しながら形が育っていきます。
5. 音が途切れると自動で完成します。`Complete` を押せば、任意のタイミングで完成させられます。
6. 完成後は `Export GLTF` で形を書き出せます。`Reset` を押せば、もう一度最初から作れます。

設定パネルからは、スタイル、成長アルゴリズム、時刻の指定、天気の条件、画面表示の切り替え、表示言語（日本語／英語）を選べます。

### 今後の展望

いま一番の課題は、数分通して眺めていると飽きることです。

打点や歌への反応は読み取れるようになりましたが、反応の種類が足りず、「次はどんな形になるんだろう」という驚きにまだ届いていません。

差を大きくすることではなく、見たことのない種類の形が出るようにすること。

ここが次の主題です。

そして、これは AI との進め方の課題でもあります。

いまあるものを改善する方向であれば、AI は速く、数も出してくれます。

ただ、想像の範疇を超える方向の案は、そのままでは出てきません。

過去の延長でうまくいきそうなものが、優先されるからです。

何が面白いかを決めるのは人の側で、そこを手放すと、破綻はしないけれど驚きもないものへ収束していきます。

この見極めを、もっと早い段階でできるようにしたいと考えています。

もうひとつは、ルールを決める時期です。

最初にルールを敷かなかった領域は、後から取り返しがつきませんでした。

どこを人が触り、どこを AI に任せるのか。

その線引きは、作り始める前に決めておくべきものでした。

三つめは、判断の往復にかかる時間です。

AI は見た目を判断できないので、最終的な合否は必ず人が実機で見て決めます。

ここは今後も変えるつもりはありませんが、人が見る回数を減らさずに、一度に見比べられる量を増やしたい。

道具の側でそこを工夫していきたいと考えています。

そのうえで、この作品を「聴いた記憶を持ち帰れるもの」として仕上げたいと考えています。

LIVE 会場でその場の音を聴かせて持ち帰る、同じ曲を複数人で聴かせて見比べる、書き出した形を実際に立体出力する。

音楽を聴いた体験が物として残ることの面白さを、もう少し先まで押し進めたいと思っています。
