## この層が達成すべきこと（2026-08-10 に定義し直した）

インタビューで目的を再定義した。**以前の「曲の進行が読み取れること」は要求ではない。**
根拠と全文は [../handoff/COMMON.md](../handoff/COMMON.md)、原則は
[project-principles.mdc](../../.cursor/rules/project-principles.mdc)。

| | 内容 |
|---|---|
| **A（本命）** | 曲ごとの個性が**シルエット**に出る。遠目で別の形と分かる |
| **B** | 一曲を最後まで聴いた結果であること（進行を読める必要は無い） |
| **C** | 聞こえている出来事が目で分かる（帯域で分けること自体は目的でない） |
| **D** | リアルタイムの反応が痕跡として残る（何が起きたかは読めなくてよい） |

A の個性の源は4つとも採用: **曲調の激しさ / テンポ・リズムの種類 /
音色・楽器編成 / 明るさ・音域バランス**。

出力先は**シルエットのみ**。表面の質感・動きに曲ごとの差を担わせない。
色も個性の主役ではないが、**天気・時間による色変化は消してはいけない**。

### [P1] 曲の時間軸を形に残す（地層 / 蓄積の本丸）

- status: **却下（2026-08-10）**。parked ではなく、方向として取り下げ
- ease: hard
- 寄与: —
- notes: |
  **2026-08-10 追記 — この項目はもう再開しない。**
  ユーザーインタビューで「曲の進行度合いを形で表す必要はない」と明言された。
  地層が駄目だった理由も「振幅不足」ではなく**「そもそも面白くなかった」**。
  つまり時間 → 位置の写像という方向自体が要求ではなかった。**再試行しない。**

  ただし以下の調査結果は捨てない。理由が変わって生き残る:
  - **クランプ飽和で長い曲ほどどの曲も似たブロブへ収束する**という部分は、
    新しい本命要求 A（曲ごとの個性がシルエットに出る）に真正面から反する。
    むしろ以前より重要度が上がった。
  - audioSalt のスクロールも、時間対応が付かないこと自体は問題ではなくなったが、
    **曲の特徴がシルエットに固定されず塗り替わる**点は要求 A の障害として残る。
  → 上の「完成形に『曲の記録』を焼き込む」で扱う。

  以下は当時の記録（読むときは上の但し書きを踏まえること）。

  背景（2026-08-06 の精査で発見。それまでどのリスト項目もこの層を扱っていなかった）:
  原則の中核要求「曲の展開や構成が読み取れる」「静と動の違いが形状に残る」が
  **原理的に成立しない実装**になっていた。
  - 蓄積の器（accumulated / midBumps / highSpikes / algoIdentity）は加算式で正しく貯まる。
  - しかし堆積先を決める空間パターンが audioSalt（= spectralPhase*1.7 + carvingPhase*0.9,
    main.ts:5515付近）依存で、この位相は曲の進行とともに単調増加する。
  - つまり時間が進むと**パターンがスクロールし**、後半の音は前半とは別の場所に積まれるのではなく
    表面全体を塗り替えるように分散する → 長い曲ほど平均化され、どの曲も似たブロブに収束。
  - accumulateWithMemory の上下限クランプも重なり、飽和して曲間の差が消える。
  過去に何度も試した係数調整（勝者強調 pow 2.05、種 confidence ゲート、winBoost 等）が
  どれも効かなかった真因はこれ。完成時のコントラスト付け直し（別項目）は対症療法であり、
  演奏中に時間軸を積み上げる仕組みそのものが欠けていた。

  方向性（ユーザー選択: 地層型）:
  曲の進行を彫刻の軸上の位置へ対応させる。イントロは下、サビは中央、アウトロは上に積む。
  静かな部分は細いまま／盛り上がりは太くなるので、上下を眺めれば曲の構成がそのまま輪郭として
  読める。他の候補（年輪型=内→外／位相スクロールを止めるだけの最小修正）は不採用。

  実装（main.ts）:
  - `getStrataCenter()` を新設。曲の長さは事前に分からないため、経過時間を
    飽和する指数カーブ `1 - exp(-t / TAU)`（TAU=150秒）で [0,1) へ写し、
    軸上 -0.85〜+0.85 へ配る。60s→0.33 / 120s→0.55 / 180s→0.70 / 300s→0.86 で、
    序盤ほど軸を広く使い長い曲では後半が緩やかに圧縮される（無限に伸びない）。
  - 堆積ループ内で、現在の高さに近い頂点ほど強く積むガウス重み `strata` を計算し
    （STRATA_SIGMA=0.38）、bulk/mid/high/identity の各デルタへ乗算。
  - 帯の外にも `STRATA_FLOOR`=0.25 を残し、層が輪切りに分断されて生き物に
    見えなくなるのを防ぐ（＝機械的な年輪にはしない）。
  - ライブの揺れ（liveOffset 等）は等倍のまま。地層は永続レイヤーのみに効かせる。
    → 見えているリアルタイムの反応量は一切減らない（原則の「リアルタイムは同格」を守る）。
  副次効果: 各高さは自分の時間帯にしか堆積を受けないので、クランプ飽和が
  「全体が一様に振り切れる」形では起きにくくなり、静かな帯と激しい帯の差が残りやすい。

  実装中に見つかった第2の原因（重要）: `bleedLiveIntoSculpture()` が
  accumulated / midBumps / highSpikes へ**もう一つの堆積経路**を持っており、
  こちらは地層を通さず毎フレーム全頂点へ均一に書き込んでいた。
  そのため accumulateBassPressure 側で付けた地層のコントラストが洗い流されていた。
  → 同じ strata 重みをこの3経路にも適用（main.ts:6126〜6205 付近）。

  検証（実測。TAU を 40 秒へ一時的に縮めて headless で堆積分布を軸方向8分割で集計）:
  - 修正前（bleed が地層無視）… 88秒時点の下→上プロファイル:
    0.207 / 0.212 / 0.252 / 0.256 / 0.244 / 0.238 / 0.263 / 0.309（ほぼ平坦・1.5倍）
  - 修正後 … 同 88秒時点:
    0.086 / 0.111 / 0.145 / 0.158 / 0.158 / 0.173 / 0.192 / 0.206（下から上へ単調増加・2.4倍）
  - 決定的な確認: 上端(+0.75)は 9秒時点では 0.0076 しかなく、帯が到達した後の
    88秒で 0.2058 まで育った。一方 下端(-1.00) は 0.0211 → 0.0858 と伸びが緩やか。
    → 「各高さが自分の時間帯にだけ材料を受け取る」が実際に成立している。
  - `STRATA_FLOOR` は当初 0.25 にしていたが、帯の外にいる時間の方が圧倒的に長いため
    床の積算が帯の積算を上回って平坦化していた。0.08 へ下げた。
  - シミュレーション時間は実時間とほぼ 1:1（wall 89s → sim 84.8s）で進むことも確認済み。
    deltaTime は main.ts で 0.033 秒に上限クランプされているが、実害は無い。
  - tsc 通過、console error 無し。診断用の計測コードは削除済み。

  確認してほしい点:
  - `npm run dev` で1曲通しで聴いて complete し、完成形の上下に曲の展開が
    輪郭として読み取れるか（静かな部分＝細い／盛り上がり＝太い）
  - 展開の違う複数曲で、シルエットがはっきり別物になっているか
  - 「地層」が機械的な輪切りに見えていないか（生き物らしさが壊れていないか）
  調整の勘所: main.ts の `STRATA_TAU_SECONDS`（軸の使い切り方＝曲長への追従）、
  `STRATA_SIGMA`（層のなだらかさ）、`STRATA_FLOOR`（層の独立性 vs 一体感）。

  撤回範囲: STRATA_* 定数・getStrataCenter()・accumulateBassPressure と

  ここから学べたこと（再開時に必ず読むこと）:
  - 数値上の改善（軸方向プロファイルの勾配 1.5倍→2.4倍）は**体感の差にならなかった**。
    つまり「軸に沿った太さの分布」は、人が見て曲の違いと感じる特徴量として弱い。
    次に蓄積を扱うときは、勾配を強めるより**別の特徴量**（例: 突起の有無・数、
    穴やトポロジー、全体の縦横比、非対称性など、輪郭として一目で分かるもの）を狙う方がよい。
  - 一方で**診断そのものは有効**なので流用できる:
    (a) 堆積先を決める空間パターンが audioSalt 依存で曲の進行とともにスクロールし、
        後半の音が前半の場所を塗り替える
    (b) accumulated / midBumps / highSpikes には **2つの独立した堆積経路** がある
        （accumulateBassPressure と bleedLiveIntoSculpture）。片方だけ触っても
        もう片方が均一に書き込んで効果を打ち消す。実際これで一度ハマった
    (c) accumulateWithMemory の上下限クランプで長い曲ほど飽和する
  - 計測手法も再利用可: STRATA_TAU を一時的に縮めて headless で走らせ、
    accumulated を軸方向8分割で集計すると分布の変化が数値で追える。
    なお deltaTime は 0.033 秒にクランプされているが、シミュレーション時間は
    実時間とほぼ 1:1 で進む（wall 89s → sim 84.8s）ので headless 計測は素直に使える。
