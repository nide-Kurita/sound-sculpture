## この層が達成すべきこと（2026-08-10 に定義し直した）

インタビューで目的を再定義した。**以前の「曲の進行が読み取れること」は要求ではない。**
根拠と全文は [../handoff/COMMON.md](../handoff/COMMON.md)、原則は
[project-principles.mdc](../../.cursor/rules/project-principles.mdc)。

| | 内容 |
|---|---|
| **A（本命）** | 曲ごとの個性が**シルエット**に出る。遠目で別の形と分かる |
| **B** | 一曲を最後まで聴いた結果であること（進行を読める必要は無い） |
| **C** | 聞こえている出来事が目で分かる（帯域で分けること自体は目的でない） |
| **D** | リアルタイムの反応が痕跡として残る（何が起きたかは読めなくてよい） |

A の個性の源は4つとも採用: **曲調の激しさ / テンポ・リズムの種類 /
音色・楽器編成 / 明るさ・音域バランス**。

出力先は**シルエットのみ**。表面の質感・動きに曲ごとの差を担わせない。
色も個性の主役ではないが、**天気・時間による色変化は消してはいけない**。

  調査で分かった根本原因: structure-tracker.ts は瞬間値（EMAと状態機械）だけで、
  曲全体のタイムラインを保持していない。一方 species-profile.ts は曲全体の平均・分散を
  ちゃんと蓄積しているが、organic/aggressive/rhythmic という3つの連続スカラーに
  圧縮された上で5つの連続モーフ重みへ滑らかにブレンドされるだけなので、
  この3次元の"中くらい"に集まる曲同士は最終的にほぼ同じブロブになる
  （＝過去の勝者強調pow等の係数調整がすべて効かなかった理由）。
  さらに致命的だったのは complete() 自身のコメント「永久メモリはすでに追従済みなので
  触らない（ハード再計算すると形がずれる）」——つまり complete() は意図的に形状に
  一切手を入れない設計だった。蓄積の主体である vectorField（アンカー由来の方向性変位）・
  sculptureMemory/erosionField（法線方向のスカラ変位）はどれも発散防止のため
  頂点ごとに上限クランプされており、ある程度アクティブな曲ならほぼ全頂点が
  上限付近まで飽和する。つまり「蓄積の器」自体は曲ごとに正しく違う値を持っているのに、
  上限に張り付いて曲間の差が最終形に出にくくなっていた。
  実装（bakeFinalSculptureMemory / applySculptureMemoryBake, main.ts:4333〜）:
  - 新しいモーフ系を足すのではなく、既存の vectorField・sculptureMemory・erosionField を
    「この曲で実際に観測された最大値／平均値の比」を基準にコントラストを付け直す
    （最大/平均比が大きい＝一部だけ突出して育った曲ほど強く、突出のない曲は無変化）。
  - 曲の音量・長さに依存しない自己参照的な正規化なので、新しい追跡用データ構造は不要。
  - 即座に書き換えると complete() の瞬間に形がポップするため、実際の適用は
    updateAfterlife() 側で完成アニメーション（既存の ease 0→1, 約6秒）に乗せて行う
    （bakeFinalSculptureMemory は「元の値」と「最終倍率」を確定するだけ）。
  検証: tsc --noEmit通過。実機で「02 Fury Of The Storm」（歪みギターの壁、密で均一）と
  「02 AIR」（静かめ）をそれぞれ20秒再生してcomplete、完成アニメーション後（7秒待ち）の
  形をスクリーンショットで確認。console error無し、ジオメトリの破綻（NaN等）無し。
  2曲で色（マテリアル側は曲パレット由来なので当然差はある）だけでなく、シルエットの
