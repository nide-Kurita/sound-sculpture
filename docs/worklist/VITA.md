### [P1] 鉱物感の課題（2026-08-17 ユーザー指摘・優先度順）

- status: doing（2026-08-17 **実機で未達確認・原因をコード上で特定**。修正は未実装）
- ease: hard
- 寄与: リアルタイム / 完成形 / 蓄積
- notes: |
  曲の種類で鉱物のような特徴を付与できるように調整してきた結果の、現状の課題。
  **優先度はこの並びどおり**（上ほど先）。

  **2026-08-17 実機確認（Fury を約10秒再生 → Complete）:**
  - LIVE 中は鉱物感がまったく分からない。
  - Complete すると、LIVE から予測できない鉱物らしい変化が一気に出る。
  - 問題は (a) LIVE で鉱物感を読めないこと、(b) 完成が LIVE の連続した到達点に見えないこと。
  - **熟成度の値を下げるのは解決ではない。** LIVE の鉱物感をさらに隠すため、問題の本質と逆。

  | # | 課題 | 既存項目との関係 |
  |---|---|---|
  | 1 | **完了にした瞬間に、LIVE で出ていなかった鉱物感が急に出る → 徐々に鉱物化してほしい** | 既存 [P1] 熟成度（maturity）の本命。実装 2 巡目まで済み・**実機確認待ち** |
  | 2 | **LIVE 時に鉱物感を表現できていない** | 同上。原因調査は「補足: 鉱石が完成時にしか出ない」に記録済み。熟成度 step 2〜3 が吸収先 |
  | 3 | **完了時の鉱物感が強く出過ぎている** | **競合あり（要判断）**。下の「競合」参照 |
  | 4 | **鉱物の種類が鉄・アルミっぽい金属感に寄っている。クリスタル／水晶のような六角柱・六角錐も欲しい**（生成＝形は後回し可）。**透明感のあるクリスタル素材の部分も欲しい** | 新規。既存宝石は「暗地＋稜＋金属寄りの鏡面」寄り。形の語彙は COMMON のファセットと別物 |

  #### 競合（エージェント判断。コードを触る前にユーザーへ確認すること）

  **A. #1・#2 ↔ 既存 [P1] 熟成度（実機で未達確定）**
  - 熟成度プランの狙いは同じだったが、**10秒で Complete する経路を満たしていない**。
  - 原因1（完成時の段差）: `updateMaturity()` の completed 分岐が、完成直前の現在値を無視して
    `0.9 + 0.1*ease` を target にする。10秒時点の maturity が低くても、Complete の最初の更新で
    **少なくとも 0.9 へ即時ジャンプ**する。コメント「瞬間の段差を作らない」と実装が一致していない。
  - 原因2（LIVE で見えない）: `syncGemFacets()` が結晶面の選択を
    **`mineralAxis × maturity`** にしている。Fury の鉱物軸が上がり始めても、序盤の低い maturity を
    さらに掛けるため、LIVE の結晶面を二重に抑えている。
  - その直後、完成時の maturity 0.9 ジャンプが `syncGemFacets()` と
    `applyCompletionFinish()`（`max(ease, maturity)`）の両方へ入り、面数と磨きが同時に出る。
    **これが実機で見えた「完了すると一気に鉱物化」の直接原因。**
  - したがって熟成度の定数を下げる調整では直さない。必要なのは配線の分離:
    1. 結晶面の早期出現は鉱物軸を主にして、maturity で全消ししない（LIVE で曲の鉱物性を読ませる）。
    2. maturity は磨き・透明感など「熟していく強さ」を連続化する役に絞る。
    3. Complete 後は固定の 0.9 から始めず、**完成を押した時点の maturity を始点**にして 1 へ補間する。
  - 係数を決める前に Fury 10秒時点の `window.__mineralAxis` / `window.__maturity` /
    結晶面数を記録し、修正後は同じ10秒 Completeで比較する。

  **B. #3「完了時が強過ぎ」↔ 熟成度プランの禁止事項**
  - 熟成度 [P1] の合意・やらないこと: **「完成側の見た目を弱めて LIVE に近づけるな。完成は到達点。上げるのは LIVE 側だけ。」**
  - ユーザーの #3 は**完成側を弱めたい**＝その合意と正面衝突。
  - 取りうる方針（どれか選んでもらう）:
    1. **完成の到達点を下げる**（`DEFAULT_GEM_*` / clearcoat・sheen の完成値を弱める）。熟成度の到達点も一緒に下がる。
    2. **到達点は維持し、LIVE 側をもっと寄せる**（#1・#2 優先。#3 は「急に出るショック」が消えたあとに再評価）。
    3. **結晶面／宝石だけ完成上限を別ノブで下げる**（磨き全体は触らない）。
  - **いま係数で完成を弱めないこと。** 方針 1 or 3 にするなら合意後。

  **C. #4 クリスタル素材 ↔ 既存 [P2] 宝石マテリアル（強度確定待ち）**
  - 既存は「結晶面の地を暗く落として艶と稜で見せる」（ユーザー選択済み・第3版）。
  - #4 の「透明感のあるクリスタル」は**地を暗くする方針と反対方向**（透過・屈折・クリアな面）。
  - 既存パネルに「透過 / 分散(fire)」はあるが、到達イメージは水晶／六角柱ではない。
  - **六角柱・六角錐の生成（幾何）は後回しでよい**（ユーザー明示）。先にやるなら**材質の透明クリスタル成分**だけ。
  - 既存 `#mineral-panel` の強度確定と同時に触ると、金属寄り仮値と透明クリスタルが混ざる。
    **強度確定を先に閉じるか、クリスタルを別チャンネル（結晶面の一部だけ透過）にするかを決めてから。**

  **D. COMMON [P1] 音色→形の語彙（ファセット強度確定待ち）**
  - COMMON はシルエットの角ばり。#4 の六角柱は**造形の種類**なので COMMON／vita 造形語彙の延長。
  - いまは「生成は後回し」なので COMMON の強度確定とは当面競合しない。
    着手するときは per-vertex 変形予算・「球の半径揺らしで種類を増やさない」原則に注意。

  #### 進め方（合意後）

  1. Fury 10秒時点の鉱物軸・熟成度・結晶面数を測る。
  2. `axis × maturity` の二重ゲートを分離し、LIVE の鉱物性と熟成の役割を分ける。
  3. Complete の maturity を「現在値 → 1」の補間へ直し、10秒 Completeでも段差を作らない。
  4. #3「完成が強過ぎ」は上記の予測不能な段差を直した後に再評価する。
  5. #4 は「透明クリスタル材質（結晶面の一部）」を別項目として切る。六角柱幾何は Parked か後続。

### [P1] LIVE から完成へ向かう「軌跡」を見せる（熟成度 maturity）。**プラン合意済み**

- status: doing（2026-08-17 **残っていた飛びを詰める2巡目まで実装済み**。
  膜の地を「完成後の呼吸ドライブ」へ寄せる形に作り直し（8/13 に入れた
  `matureGround` の**回帰＝完成側を 55% 弱めていた件を修正**）、
  種プロファイル倍率・凍結・待機ゆらぎ・粒子の湧き・駆動の平均化まで。
  **残りは実機確認だけ。** 実測表は [../handoff/VITA.md](../handoff/VITA.md) 3章の最上段）
- ease: hard
- 寄与: リアルタイム / 蓄積 / 完成形
- notes: |
  ユーザー要望（2026-08-13・チャット）:「complete の時と Live の時の見た目が全く違うので、
  Live の時から complete に向かう軌跡を見れるようにしたい。」

  下の「鉱石が完成時にしか出ない」（2026-08-12 の調査）は**この項目の一部**。宝石だけの話ではなく、
  **軸 0 のアコギ曲でも完成時に clearcoat 0.42 / sheen 0.55 が立ち上がる**ので、
  同じ飛びが全曲で起きている。宝石はこのプランの step 2 として吸収する。

  #### 合意事項（2026-08-13。AskUserQuestion で確定）

  1. **熟成度の駆動 = 蓄積量だけ**（曲の進行度・経過時間は使わない）。
  2. **LIVE の終端で完成の 90%** まで寄せる（＝完成はほぼ凍結だけ。軌跡を最大限見せる）。
  3. **寄せる範囲 = 磨き ＋ 宝石 ＋ 膜 ＋ 彩度 ＋ 環境（背景・ライト）**。

  #### 設計（発明しない。承認済みの完成値へ向かう途中を出すだけ）

  `maturity`（熟成度 0→1）を **1 本**持ち、いま完成の瞬間に切り替わっている値を
  `lerp(LIVE 値, 完成値, maturity)` に置き換える。**新しい LIVE ルックを作らない**
  （完成の見た目はユーザー承認済み。途中を出すだけなので合意済みの到達点を動かさない）。

  | チャンネル | いまの LIVE | 完成 | 扱い |
  |---|---|---|---|
  | core の磨き clearcoat / sheen / iridescence / roughness | 1e-4 / 1e-4 / 1e-4 / 0.86〜0.92 | 0.42 / 0.55 / 0.34 / 0.78 | **寄せる** |
  | 宝石の光学（結晶面の磨き `gemFinish`） | 0（完成の ease 専用） | 割合 × 強度 | **寄せる** |
  | 膜の不透明度 | 上限 0.46（alpha 天井 0.55） | 0.20 | **寄せる** |
  | 彩度 | 0.235（実測） | 0.130（実測） | **寄せる**（色相は動かさない。色は脇役） |
  | 環境（背景色・キー/フィル/アンビエント） | forming 値 | complete 値 | **寄せる**（`envMix`） |
  | ヒット（低→パルス / 中→膜の線・フラッシュ / 高→粒子） | — | — | **据え置き。1 つも弱めない** |
  | 幾何の焼き込み `applySculptureMemoryBake` | 未適用 | ease で適用 | **触らない**（作品確定の意味） |
  | 動きの凍結（`uCompleted`）・粒子の消滅・最終パレット確定・`finalizeProfile` | — | — | **触らない**（完成の特権） |

  **地（質感・不透明度・彩度・環境）は完成へ寄せる / 出来事（打点の反応）は最後まで同じ強さ**
  が切り分けの原則。リアルタイム性は完成形と同格（原則ファイル）なので、
  膜を薄くしてもヒットの光は据え置き＝薄い地の上でむしろ読みやすくなる方向に持っていく。

  #### step 0 — 蓄積量の候補を全曲で実測してから正規化を決める（**ここから始める**）

  **駆動を「蓄積量だけ」にしたので、正規化を推測で決めると必ず外す。** 地雷が2つある:

  - **早期飽和**: `formDevelopment` は「序盤の球を守るゲート」として作られていて**すぐ 1.0 に張り付く**。
    そのまま使うと 20 秒で熟成度が振り切れて軌跡が見えない。**そのまま使わないこと。**
  - **静かな曲が寄らない**: Donna Lee / I'm Yours は蓄積が小さく、LIVE 終端で 0.9 に届かない可能性。
    その場合は完成の飛びが残る（＝今回の要望が静かな曲では満たされない）。

  やること: `maturity_probe.js`（新規）を作り、**9 曲すべて**で候補指標の時系列を 5 秒おきに記録する。
  候補は最低この3つ:

  1. `formDevelopment`（既存。飽和の速さを確認する対照）
  2. 変位の総量: `mean(|vectorField|) + mean(|sculptureMemory| + |erosionField|)`
  3. 音の露出の積算: `Σ bands.overall * dt`（単調増加・飽和しない）

  読み出しは `window.__mineralAxis` と同じやり方で `window.__maturity` を生やす（dev のみ）。
  **軸のときと同じ理由で、見えない量は決められない。この読み出しは消さないこと。**

  判定: 曲の 20% 時点で 0.9 に達していない／曲の終端で 0.7 以上、を全 9 曲で満たす正規化を選ぶ。
  **どれも満たせなければユーザーに再相談**（「蓄積量だけ」では両立しない可能性がある。
  そのときの代案は「完成時の蓄積量で自己正規化」だが LIVE 中は最終値が分からない、という難点を
  そのまま説明して判断を仰ぐ）。実測なしに係数を捏ねないこと。

  #### step 1 — maturity を1本作って配線する（見た目は変えない）

  - `SoundSculpture` に `maturity`（0〜0.9）と `updateMaturity(deltaTime)` を追加。
    - step 0 で選んだ蓄積量 → 正規化 → **単調増加**（`Math.max` で下がらせない。
      下がると「戻った」に見えるし蓄積の原則に反する）→ 1 秒程度の追従で滑らかに。
    - 上限 `MATURITY_LIVE_CEILING = 0.9`（合意事項2）。完成後は
      `0.9 + 0.1 * completionProgress の ease` で 1 へ。**完成の瞬間に段差を作らない。**
  - `getMaturity()` を公開（環境クロスフェードが外から読む）。dev パネルに**熟成度の表示と手動 override**
    （軸の override と同じ作り）を付ける。**override が無いと実機で追い込めない。**
  - この step では**まだ見た目を変えない**（配線と読み出しだけ）。console error 0 / tsc を通す。

  #### step 2 — 磨きと宝石を maturity で立ち上げる（本命。宝石[P1] の吸収先）

  - `main.ts` L5477〜5500: 形成中に `FINISH_EPSILON` へ固定している else 側を
    **`完成値 × maturity`** にする。上げる順は **clearcoat → roughness の鋭化 → iridescence → sheen**。
    **白飛びを1つずつ確認しながら**（ブルーム 0.80 / 2.08 との合成で飛びやすい。
    形成中に上げてこなかった理由が「回転でスペキュラ白飛び・色が飛ぶ」なので、ここが一番危ない）。
  - `applyCompletionFinish` は **`Math.max(現在値, 完成値 × ease)`** にして、
    LIVE で先に上がったぶんを完成の瞬間に**下げてしまわない**ようにする。
    完成の確定値（clearcoat 0.42 / sheen 0.55 / iridescence 0.34 / roughness 0.78）は**動かさない**。
  - 宝石: `gemFinish = getCrystalFaceRatio() * uGem.value * max(maturity, ease)`。
    結晶面の枚数は軸が決めるまま（`MINERAL_GRIT_*` の3定数は触らない）。
  - 膜シェーダ（`GEM_MEMBRANE_FRAGMENT` の直後）: いま結晶面の alpha 天井を
    `0.55 + gGemMask*0.06` と**上げている**のを**下げる**向きへ（結晶面の上だけ 0.30 付近）。
    稜と鏡面の加算は残す＝「白く盛る」のではなく「透かす」。
  - **結晶になる面の枚数も maturity で開く。** `syncGemFacets` の
    `smoothstep(rank, rank+0.08, axis)` を **`axis * maturity`** にする
    （軸＝最終的な枚数 / maturity＝いま何枚目まで結晶化したか）。
    軸は 10〜40 秒で飽和するので、これが無いと**面の枚数だけ序盤で止まって軌跡にならない**
    （2026-08-12 の実測: Fury は 40 秒で 18 面すべてが結晶）。
    `MINERAL_GRIT_*` の3定数と 9 曲の calibration は**壊さない**（最終枚数は変わらない）。
    ウォームアップ 8 秒（`fibSeconds(5)`）も残す（出だしで結晶を出さない仕様）。

  #### step 3 — 膜の不透明度と彩度を maturity で寄せる

  - `membraneOpacity`（L8046〜）の LIVE 上限 0.46 を **`lerp(0.46, 0.20, maturity)`** に。
    `opacityScale: 1.45` と `completedOpacity: 0.2` は**動かさない**。
    `uCompleted`（凍結）は maturity では動かさない（**動きは完成の特権**）。
  - 彩度: 実測で LIVE 0.235 → 完成 0.130。**色相は 1 度も動かさない。**
    下げるのは彩度の倍率だけ（粘土の per-pole 彩度と膜の pearl 側）。
    混色の確定値（spread 0.28 / balance -0.1）・膜の真珠シアン（案A）・
    曲の色の幅（hue 0.4 / sat 0.55）は**触らない**。
  - **生物面（`gGemMask == 0`）と軸 0 の曲でも、磨き側の軌跡は出す**
    （宝石ではなく「生きもの → 作品」の質の変化として）。

  #### step 4 — 環境（背景・ライト）を寄せる

  - `updateEnvironmentCrossfade`（L11040〜）の `target = isComplete ? 1 : 0` を
    `isComplete ? 1 : sculpture.getMaturity()` にする。`envMix` は既に背景色・key/fill/ambient/rim を
    まとめて lerp しているので**ここ1箇所で済む**。
  - 天気・時刻の色変化は殺さない（絶対条件）。`daytime-preview` / `weather-preview` で
    環境を固定して、寄せたあとも天気差が残っているかを確認する。

  #### step 5 — 検証（省略しない。数値目標つき）

  before 値（`completion_gap_stats.js`、Fury・各フェーズ5枚平均。2026-08-13 実測）:

  | フェーズ | 稜・鏡面 | 白い薄膜 | 輝度 | 彩度 | 局所コントラスト | 面積 |
  |---|---|---|---|---|---|---|
  | LIVE 60 秒（軸 1.00） | 3.08% | 35.4% | 0.599 | 0.235 | 0.0536 | 22.4% |
  | 完成 +2 秒 | 8.46% | 38.1% | 0.575 | 0.155 | 0.0380 | 29.3% |
  | 完成 +11 秒 | **7.32%** | 40.5% | 0.583 | **0.130** | 0.0423 | 25.9% |

  **変化のほぼ全部が完成 +2 秒までに終わっている**（6 秒の完成アニメーションは飛びを均していない）。

  - **目標: LIVE 終盤で live→done の差の 90% を消化**（合意事項2）。
    稜・鏡面 3.08% → **6.9% 付近**、彩度 0.235 → **0.14 付近**。
    完成の瞬間の残差が各指標で今の 1/10 になっていること。
  - `maturity_probe.js` で **9 曲すべて**の熟成度カーブ（早期飽和していないか／終端で 0.7 以上か）。
  - **LIVE のヒットが1つも弱まっていないこと。** 低→パルス / 中→膜の線 / 高→粒子を
    再生中に確認する（`gem_playback_shot.js` / `flash_check.js`）。ここが弱ると原則違反。
  - 軸 0 の曲（I'm Yours / Donna Lee）で軌跡が出ていること＆宝石が出ていないこと。
  - **白飛び**（ブルーム 0.80/2.08 との合成）。飛んだら sheen → iridescence → clearcoat の順に下げる。
