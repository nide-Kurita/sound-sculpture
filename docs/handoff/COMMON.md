## 1. 目的・ゴール

スタイルに依らない層（帯域解析・リズムイベント・蓄積・完成時の焼き込み）を扱う。
`vita` も `aether` も同じ `bands` / `rhythm` / `structure` を受け取るので、
ここを触ると**すべてのスタイルに効く**。

**スタイルは1つに絞らない。** 同じ曲を違うスタイルで見られること自体が作品の価値
（2026-08-10 ユーザー確認）。新しいスタイルを足すのが安く済む構造を保つこと。
この層に特定スタイルの語彙（粘土・膜・粒子など）を持ち込まない。

### この層が達成すべきこと（2026-08-10 定義）

**A. 曲ごとの個性がシルエットに出ること（本命）**

何が違えば違う形になるべきか — 4つとも採用:

| 軸 | 例 |
|---|---|
| 曲調の激しさ | 静かなバラード ↔ 激しいロック |
| テンポ・リズムの種類 | 四つ打ち / シャッフル / バラード |
| 音色・楽器編成 | アコースティック1本 ↔ バンド・電子音 |
| 明るさ・音域バランス | 低音が重い ↔ 高域が輝く |

出力先は **シルエットのみ**。遠目に見ても別の形だと分かること。

- 表面の質感・模様、動き方には**曲ごとの差を担わせない**（作品としての美しさの課題）。
- 色も曲ごとの個性の主役ではない。
  ただし**天気・時間・音楽性による色変化は必須。消してはいけない**（過去に却下されている）。
- 似た曲調どうしは似ていてよい。無理に散らさない。

**B. 一曲を最後まで聴いた結果であること**

曲全体の統計・履歴が最終形を決めていること。これが「曲としての蓄積」。

- **曲の進行度合いを形で表す必要はない。**
  完成品を見て「ここがサビだった」と辿れる必要はない（2026-08-10 ユーザー明言）。
- つまり蓄積とは**時系列を空間へ写像することではない**。曲全体の特徴を最終シルエットへ
  収束させること。

**C. 聞こえている出来事が、目で分かること**

これが LIVE 側の不変の要求。**帯域で役割分担すること自体は目的ではない**（手段）。
割り当てはスタイル側で決めてよい。

**D. リアルタイムの反応が痕跡として残ること**

「何が起きたか」を読み取れる必要はない。
「反応した結果としてこの形になった」と感じられればよい。

### 2026-08-20 LIVE の検出・合成を直した（**vita の [P0] 由来。classic 全スタイルに効く**）

vita で「密な曲では LIVE の動きが見て取れない」を実測したところ、**エンジン側の飽和**が真因だった。
2026-08-10 に「ひとまず完了」としていた LIVE リズムの見直しにあたる。詳細な実測表と
定数は [VITA.md](VITA.md) 3章の最上段。ここには**この層に入った変更だけ**を書く。

1. **帯域ノイズゲートの飽和でオンセットが消えていた。**
   `smoothstep(a, b, v)` は b 以上を全部 1 にするので、大音量の曲では帯域値が 1 に張り付き、
   **その差分（＝オンセット）が 0 になる。** Fury の高域は 15 秒間ずっと 0.999 で、
   **ライドが鳴り続けているのにハットが 1 回も検出されなかった**（hat 平均 0.005）。
   → `RawBands`（ゲート前の帯域）を `AudioInput` から `RhythmDetector.update()` まで通し、
   生の差分に**ゲート区間の傾き 1/(b-a)**（`RAW_ONSET_GAIN`）を掛けて `Math.max` を取る。
   **飽和していない曲では値がほぼ一致する＝検出感度は変えていない。**
   決定論経路（`DeterministicSimStep`）とライブ解析の両方に入れてある。
2. **ハット検出が「キック／スネアと同時なら丸ごと捨てる」だった** → 同時なら ×0.6 に。
   適応ゲートの係数 0.4 → 0.24、`onsetHigh > onsetMid*0.55` → `*0.35`。
   粒子は低音・中音とは別の視覚チャンネルなので、同時に出ても視覚渋滞にならない。
   **原則の「抑制は同時多発の視覚渋滞用であって、密な曲を丸ごと大人しくする手段ではない」。**
3. **硬い天井（`clamp01` / `Math.min`）→ `softCeil`**（knee 0.62 までは恒等、上は漸近）。
   天井で切ると超えたぶんの順序が消え、密な曲では「ずっと最大＝変化が見えない」になる。
4. **同時多発の合成を「和」→ `combineEvents`（一番強いもの＋残りの 0.5 倍）。**
5. **打点の局在**（`spawnStrike` / `strikeFieldAt`）: 音色の高さ（centroid）を 12 段に
   量子化して経度、帯域を緯度に写し、その方向のローブだけが応える。
   `liveOffset` は永久層へ転写されるので**蓄積（曲ごとの個性）にも効く。**

**確認**: 7 スタイル（vita / aether / volume / monolith / metamorphosis / lumen / dither）で
Fury を 25 秒再生して console error 0。曲間のシルエット差は 0.400〜0.544（床 0.022〜0.027）。
`tsc` / `build` 通過。**実機確認は未了。**

### 2026-08-12 膜（外殻）にも結晶ファセットを効かせた（要求 B）。2パスの面ドメイン平均

輪郭を作るのは膜なので、core だけ faceting しても遠目のシルエットが角ばらなかった。
そこで膜にも faceting を入れた。**ただし大域平均の面へ寄せると膜のふくらみが全部潰れて
球になった**（`applyGlobalForm` に膜の平均半径を渡した初手が失敗。実測: 軸 0.5 で球化）。

**対処**: `applyMembraneFacets`（2パス。`main.ts`）。
- pass1: 各頂点を最も近い結晶面へ割り当て、**面ドメインごとに面法線方向の距離 dot(p,m_k) の平均**を出す。
- pass2: 各頂点を「自分のドメインの平均距離」の面へ寄せる。
- **大きな起伏は面ごとの距離差として残り、面内だけ平らになって境界に稜が立つ**＝球化しない結晶。
- `relaxMembraneFolds` の**後**に呼ぶ（稜が smooth で消えないように）。axis 0 で効果なし。
- 膜の `applyGlobalForm` 側の faceting は `refRadius=0` で skip（2パスへ一本化。core は従来どおり）。

検証（`mineral_facet_sweep.js`、Fury 凍結・軸 0/0.5/1）: **球化は解消、形は保たれた**。
**2026-08-12 追記: 角ばりを強めた** — `facetCount` 11→**18**（結晶面を増やす）、
膜の faceting 上限 0.55→**0.85**（面ドメイン平均なので球化しない）。core 側は単一パスで
球化しやすいので 0.55 のまま。軸 1 で膜の外殻が締まり輪郭が明確に角ばる（軸 0 は丸い塊）。
画像 `docs/vita-progress/mineral-membrane-facet-sweep.png`。`tsc`/`build` 通過、console error 0。
**残**: strength の既定は曲を鳴らしてユーザーが決める。膜は半透明なので輪郭は控えめ。

### 【2026-08-10 訂正】「どの曲も似た形へ収束する」は実測では起きていなかった
