# 引き継ぎメモ（handoff）

**調整のたびに、そのスタイルの引き継ぎメモを更新する。** 例外はない。

目的は2つ。

1. **セッションを溜めない。** 会話を遡らなくても、このファイルだけで再開できる状態にする。
2. **モデルや環境が変わっても困らないようにする。** Cursor と Claude Code のどちらで
   作業しても、同じファイルを読み書きする。片方でしか読めない場所に知識を置かない。

## ワークリストとの違い

- **ワークリスト** = これから何をするか（タスク）
- **引き継ぎメモ** = いま世界がどうなっているか（状態・失敗の履歴・検証方法・禁止事項）

同じことを二重に書かない。タスクの経緯はワークリストの `notes` に、
再開に必要な状態と地雷は引き継ぎメモに置く。

## 書くときの原則

- **失敗を消さない。** 「試して駄目だった」は次のモデルにとって一番価値がある情報。
  なぜ駄目だったかまで書く。
- **主観で書かない。** 「良くなった」ではなく、何をどう測っていくつだったかを書く。
  比較画像を作ったならパスを書く。
- **禁止事項は理由とセットで。** 理由が無いと次のモデルが「試してみよう」と踏む。
- 相対日付を使わない（「先週」ではなく `2026-08-09`）。
- 検証に使ったスクリプトは scratchpad に置きっぱなしにせず、
  リポジトリ内（例: `docs/aether-progress/tools/`）へ残す。scratchpad はセッションごとに消える。

## テンプレート

```markdown
# 引き継ぎメモ: <スタイル名>

最終更新: YYYY-MM-DD

## 1. 目的・ゴール
何を目指しているか。判断基準は何か（参考資料があればパス）。

## 2. いまの状態
できていること。**どこまで検証済みで、どこからが未検証か**を分ける。

## 3. 直近の変更（新しいものを上に）
### YYYY-MM-DD <一行の要約>
- 何を変えたか / なぜそう変えたか
- 測った値（あれば）
- 残った差

## 4. 未解決の問題・エラー
無いなら「無い」と書く。

## 5. すでに試して失敗したこと（繰り返さないこと）
理由つきで。

## 6. 有効だった検証方法
再現できる手順で。スクリプトのパスも。

## 7. 絶対にやってはいけないこと
理由つきで。

## 8. 次にやること
ユーザーの判断待ちなら、何を聞くのかを書く。

## 9. 新セッションで最初に読むファイル
順番に並べる。
```
