### 2026-08-10 追記: 参考動画に似せるだけでは足りない

ユーザーインタビューで作品全体の目的が定義し直された（`docs/handoff/COMMON.md` 参照）。
aether にも次が要求される。**フェーズ4（音の変調）を設計するときに効いてくる。**

- **曲ごとの個性がシルエットに出ること。** 別の曲なら遠目に見て別の形になる。
  個性の源は 曲調の激しさ / テンポ・リズムの種類 / 音色・楽器編成 / 明るさ・音域バランス。
- 出力先はシルエット。表面の質感・色・動きに曲ごとの差を担わせない
  （色は天気・時間の変化として維持するが、曲ごとの個性の主役ではない）。
- 曲の進行度合いを形で表す必要は**無い**。
- 演奏中の反応は痕跡として残ればよい（何が起きたかは読めなくてよい）。

**懸念（未検証）**: いまの aether のシルエットは `uMajor` / `uMinor` /
`uStretchX/Y` / `uTwist` / `uWarp` の狭い範囲でしか動かない。
無音のベース形を参考動画に固定した結果、**曲による差が出にくい構造になっている
可能性が高い**。フェーズ4に入る前に、性格の違う曲で完成形を並べて確認すること。
「参考に似ていること」と「曲ごとに違うこと」は両立させる必要がある。

### フェーズ1: 無音ベース（実装完了・要ユーザー判断）
すべて `src/aether-sculpture.ts` 内。以下5点が本質的な変更:

1. **発光モデル → 透過モデル**
   光学的厚み `tau` を積算し、最後に一度だけ `densityRamp(depth, warmth)` で色へ写す。
   発光モデルだと厚い所ほど明るくなり参考動画と逆になる。

2. **ソリッド球 → 自己交差する薄膜**（最重要）
   `abs(sdSphere(q, uMajor) + disp) - uShell` で殻化し、低周波変位で波打たせる。
   参考動画の「輪郭のはっきりした暗いボイド」は穴でも高密度中心でもなく、
   **折りが重なってレイが膜を何層も貫いた結果**。ソリッドな球ではリボン状の折りは
   絶対に出ない。ここが以前の版が似なかった最大の理由。

3. **`cheapNoise` を変位から追放**
   周波数が 78 rad/unit あり、塊の直径 1.1 に対して波長 0.08。折りではなく霧にしかならず、
   薄膜を斑点ノイズに砕いていた。低周波の `swell()` 関数を新設して `map()` と
   `domainWarp()` の両方で置換。これでノイズが消えて折りが出た。

4. **densityRamp の再構成**
   「彩度の乗った平坦な帯」＋「短い区間で落ちるボイド縁」。
   全域を滑らかに補間すると全部が中間色に溶けてエアブラシ画になる。
   停止点: `<0.30` pale→mid / `<0.52` mid 平坦 / `<0.66` 一気に deep / それ以上 abyss。

5. **解析的なオーラ**
   レイと原点の最近接距離から算出して tau に加算。
   ループ内は空間スキップするので拾えないため解析で足す必要がある。
   これが無いと色から背景へ直接切り替わって切り絵に見える。

その他: 寒色側の hue を純青 0.58 → ティール 0.50。マーチングを
「膜厚基準の細かい固定ステップ + SDF スキップ」に変更（`STEPS` 48→112）。

### フェーズ1 残差詰めで入れた変更（2026-08-09 夜）
本文は `docs/worklist/AETHER.md` に詳しく書いた。要点だけ:
1. **膜を3層に**（半径比 1.0 / 0.82 / 0.63）。1枚では tau が2値にしかならず帯が積層しない。
2. **ランプの座標を tau そのものに**。`1-exp(-tau*k)` は上位3割の tau を
   depth 0.60〜0.77 に圧縮し、ボイドの縁と内部の階調を作る余地を潰す。
3. **色相は tau ではなく lateral が担当**。中間帯の色相だけが場所で振れる。
   tau に寒色→暖色を直列に並べると等高線状のリングになって似ない。
4. **寒色→暖色は HSV で色相を回す（洋紅を経由・増加側に固定）**。
   RGB 直線補間は黄土色に濁り、淡色経由は乳白色に洗われる。参考の実測は
   #4f4689 → #994f82 → #fca46f。
5. **背景 #d4e8e1 とランプの pale を同一色に**。縁が背景へ溶けるのは
   alpha ではなく色の一致で作る。だから alpha は色より先に立て切ってよい。
6. **露出の正規化**。tau は uShell と uSoftness にほぼ比例するのに停止点は絶対値。
   正規化前はシードだけで暗部面積が 15%〜42% に暴れていた。

## 5. すでに試して失敗したこと（繰り返さないこと）

- **uniform の初期値だけ直す** → 効かない。`updateUniforms()` が毎フレーム上書きする。
  実際 `uAbsorption`/`uEmission` は初期値 1.15/1.0 に対し実行時 4.4/7.6 が入っており、
  depth 飽和＋白飛びで densityRamp が完全に無効化されていた。**これが「真っ青」の真因**。
- **係数を当てずっぽうで振る** → 何度も外した。原因は色設計ではなく uniform 上書きだった。
- **ソリッド球のまま色ランプだけ調整** → 折りが出ないので原理的に似ない。
- **`cheapNoise` の振幅調整** → 周波数が問題なので振幅では解決しない。
- **寒色と暖色を tau 上に直列に並べる**（青の次に橙）→ 等高線状のリングになる。
- **層番号で色を切り替える** → 大きな2色パッチと硬いクリースになる。
  色は折りを作っているうねり場そのもので駆動する。
- **ティールと橙を RGB で直接 mix** → 中間が必ず濁った黄土色になる。
- **ティールと橙を淡色経由で繋ぐ** → 塊全体が乳白色に洗われて彩度が死ぬ。
- **金・薔薇・菫・ミントの色相を円平均して第3色にする**（2026-08-10）→
  補色が打ち消し、橙に戻って混ざって見えない。一番強い色素を accent にする。
- **無音だけ見て面積比を合わせる** → 蓄積が飽和した曲の終盤で黒く潰れる欠陥を見落とす。
- **amp を下げて smin k を上げ、ボイドの鉤を溶かす**（2026-08-10）→ 折りが消えて
  Siri オーブ化し、暗部 19→14 / 淡部 13→28。面積比制約の下では幾何で角を取れない。
  色側だけで境目を柔らける。幾何は元に戻した。
  **フェーズ4の uMelt はこの失敗を踏まえ smin 上限 0.078。それ以上は上げない。**
- **キック→半径・呼吸、スネア→stretch の速いパルス**（〜2026-08-10）→
  再生中が弾み主体になる。ユーザーが却下。LIVE は flowRate / melt / 細渦へ回す。
- **帯域エンベロープを渦の主役にする + パルス減衰を遅くする**（2026-08-10 フェーズ4）→
  弾みは消えたが「音との親和性がなくなった」。FFT の大きさ追従は聴感イベントではない。
  毎フレームの salience 再点火もパルスを落とさない。打点はオンセット、余韻は Ring。
- **cross の sat を 0.68 まで落とす** → area.js の中間帯が淡部へ流れ、淡部 13→28。
  0.58 が上限。

### 有効だった診断手法（再訪時はこれを使う）

**判定を数値にすること。** 見た目の議論は主観で往復する。

1. **面積比メトリクス（一番効いた）**: 本体を「暗部 / 彩度のある中間帯 / 淡部」に
   分けて面積比を出す。参考3フレームの実測 **20.7 / 62.4 / 16.8%** を目標値にする。
   これが合っているかどうかで、係数を振る方向が一意に決まる。
2. **tau の CDF**: シェーダ出力を一時的に `vec4(tau/1.5, 0.0, 1.0, 1.0)` に差し替え、
   R チャンネルから tau を直接読んでパーセンタイルを出す。
   ランプの停止点はこの CDF に照らして置く。**幾何を変えたら必ず測り直す。**
3. `lateral` など他の中間値も同じ要領で R へ書き出せば測れる。

**aether のキャンバスはトーンマップを通っていない**ので値を直接読める
（診断色 0.5 が 128 で出ることで確認済み。以前「ACES を通るので不正確」と
書いていたのは誤り。ただし他スタイルは未確認）。

**測るときの注意:**
- 形状は常にモーフし、シードはロードごとにランダム（`reset(Math.random()*1e9)`）。
  **1枚では測れない。** 複数シード×複数フレームの平均で見る。
- 変更の効き方は非線形。露出定数 0.100→0.117 の間で暗部が 11%→33% まで動く。

**診断コードを入れたら必ず戻すこと。**

## 6. 検証方法

### 再生中の検証（headless で音が出せない場合）
音が動かすのは uniform だけなので、**蓄積とパルスを固定した状態を作って見る**のが
確実で再現性もある。`?aetherAccum=1`（曲の終盤）と `aetherSeed` / `aetherHueLock=0`
は `reset()` が読む計測用 URL として残してある（シェーダへ診断色を書く方式ではない）。
これで「無音では正常だが蓄積飽和で黒く潰れる」欠陥を捕まえられる。
**シェーダへ `gl_FragColor = vec4(tau,...)` を仕込む診断は測ったら消すこと。**

### 性能
ヘッドレス（ソフトウェアレンダ）:
- フェーズ1b 時点: aether 6.3fps / vita 5.5fps（3回平均）
- curl 導入後: aether **3.1fps**（4秒計測。オクターブを落としても同じ）
swiftshader は飽和しやすい。実機 GPU での比較が必要。落ちていたら curl を粗スケールだけにする。
